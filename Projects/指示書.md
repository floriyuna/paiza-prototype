
# AI開発指示書：paizaラーニング UX改善プロトタイプ

## 1. プロジェクト概要

paizaラーニングの新しい学習導線を提案するため、実際に操作できるWebアプリケーションのプロトタイプを開発してください。

本プロジェクトの目的は、プログラミングに興味はあるものの、積極的に学習するほどの意欲がない大学生でも、気軽にプログラミング学習を始められるUXを実現することです。

### コンセプト

**「アカウントを作る前に、まずプログラミングの楽しさを体験する」**

従来の想定：

サイト訪問 → アカウント登録 → 講座を探す → 学習開始

今回の提案：

**サイト訪問 → 簡単な質問 → 学習体験 → 達成感 → アカウント登録（任意）**

アカウント登録を学習開始の必須条件にせず、ゲストユーザーでも基本的な学習コンテンツを利用できる仕組みを構築してください。

アカウント登録は、より発展的な学習や学習記録の保存を希望した場合にのみ案内します。

## 2. 最重要UX要件

以下の条件は必ず守ってください。

1. アカウント登録を求める前に、実際の学習体験を提供する。
2. ゲストモードでも基本的な問題やミニゲームを利用できる。
3. 最初に簡単な質問を行い、プログラミング経験を把握する。
4. 回答結果に応じて、適切な難易度の問題を自動的に提示する。
5. 初回学習までの操作数をできるだけ少なくする。
6. 学習中にアカウント登録を強制しない。
7. 問題を解いた後に、なぜその結果になったのかを理解できるようにする。
8. 学習体験を完了した後、継続学習やアカウント登録を選択できるようにする。
9. 登録しない場合でも、ゲストとして基本的な学習を続けられるようにする。
10. ユーザーが何をすればよいか迷わない、直感的なインターフェースにする。

特に重要なのは、**アカウント登録そのものをゴールにしないこと**です。

最初の学習体験を完了し、ユーザーが「もう少し学んでみたい」と感じることを目標にしてください。

paizaラーニングらしいデザインを採用したトップページを制作してください。

既存の学習サイトの雰囲気を残しつつ、新しい学習体験への入り口を大きく配置します。

### メインコンテンツ

キャッチコピー：

**「まずは遊んでみよう。登録なしでプログラミング体験！」**

**「さっそく体験する」**

「講座一覧を見る」

## 画面②：簡単なアンケート

「さっそく体験する」を押した後、簡単な質問を表示します。

目的は、ユーザーのプログラミング理解度を大まかに把握することです。

### 質問例

**Q1. プログラミングをどのくらい経験したことがありますか？**

- 初めて触れる
- 授業などで少し触れたことがある
- 簡単なプログラムなら作れる
- 普段からプログラミングをしている

**Q2. 次のうち、最も近いものはどれですか？**

- コードを見ても何が書いてあるか分からない
- 簡単なコードなら何となく理解できる
- 条件分岐や繰り返し処理を理解している
- 自分でコードを書いて問題を解決できる

回答内容から、初心者・中級者・上級者の3段階に分類します。

質問はカード形式で表示し、クリックするだけで回答できるようにしてください。

質問数は最小限にし、回答後は講座一覧などを挟まず、そのまま最初の問題へ移動します。

また、回答後に難易度を手動で変更できる機能も設けてください。

# 4. メイン学習コンテンツ

## 4.1 バグ修正パズルゲーム

今回のプロトタイプで最も重要な機能です。

**最初から正常に動作しないゲームを表示し、ユーザーがコードの一部を修正することで、ゲームの動作を正常に戻す体験**を提供してください。

### 基本的なゲームの流れ

1. 画面にキャラクターと簡単なゲームステージを表示する。
2. キャラクターが意図しない動きをする。
3. 「このバグを直して！」というメッセージを表示する。
4. 問題に関係するコードを表示する。
5. ユーザーが選択肢から修正方法を選ぶ。
6. 修正後の動作をアニメーションで確認する。
7. 正しく修正できた場合は成功演出を表示する。
8. なぜバグが発生したのかを簡単に説明する。

### 初心者向けの問題例

キャラクターがジャンプしようとしても、ほとんどジャンプできない。

表示コード：

```python
jump_power = 0
```

ユーザーへの指示：

「キャラクターがジャンプできない！ 数字を変えて直してみよう！」

選択肢：

- `jump_power = 0`
- `jump_power = 5`
- `jump_power = -5`

正しい選択肢を選ぶと、キャラクターが正常にジャンプする。

変更したコードの内容とゲーム内の動作を連動させてください。

初心者でも理解しやすいように、コードの意味を知らなくても試行錯誤できる設計にしてください。

### 中級者向け

条件分岐や繰り返し処理を利用した問題を用意します。

例：

- キャラクターが障害物を避けない
- 特定の条件で動作が停止する
- アイテムを取得してもスコアが増えない

複数のコードから原因を特定し、適切な修正方法を選択します。

### 上級者向け

複数の処理が組み合わさった問題を用意します。

例：

- 条件分岐の順序による不具合
- 繰り返し処理の終了条件の誤り
- 複数の変数が関係するバグ

単に正しいコードを選ぶだけでなく、実行結果を予測する要素も取り入れてください。

ただし、プロトタイプ段階では複雑なコードエディターは不要です。

選択肢による修正を基本としてください。

---

## 4.2 コードの実行結果を予想するクイズ

バグ修正ゲームとは別に、コードの実行結果を予想するクイズを用意してください。

### 基本仕様

1. 短いコードを表示する。
2. 実行結果を予想する。
3. 4つ程度の選択肢から回答する。
4. 正解・不正解を表示する。
5. 実際の実行結果と簡単な解説を表示する。

### 問題例

```python
x = 5
x = x + 3
print(x)
```

選択肢：

- 3
- 5
- 8
- 15

正解後には、変数の値がどのように変化したのかを視覚的に説明してください。

初心者には変数や簡単な計算、中級者には条件分岐や繰り返し処理、上級者には少し複雑な処理を出題します。

# 5. 解説・学習への誘導

問題を解いた後は、正解・不正解だけで終了させないでください。

### 解説画面

以下の内容を表示します。

- 問題の正解
- バグが発生した理由
- 修正前と修正後のコードの比較
- 実行結果の違い
- 関連するプログラミング知識

さらに、関連する学習動画や講座へ移動できるボタンを設置してください。

ボタン例：

**「この仕組みを動画で学ぶ」**

「もう一問挑戦する」

「別のゲームを遊ぶ」

動画や講座は、将来的にpaizaラーニングの既存教材と連携することを想定します。

プロトタイプ段階では、実在する教材との連携が難しい場合、ダミーの講座データや解説画面を使用して構いません。

ただし、実際に連携していない機能を、連携済みであるかのように表示しないでください。

# 6. 学習終了後のアカウント登録導線

初回の問題を完了した後、達成感を得られる画面を表示してください。

例：

「初めてのプログラミング体験クリア！」

「あなたはプログラムのバグを1つ修正できました！」

簡単なアニメーションや達成バッジなどを表示しても構いません。

その後、次の選択肢を提示します。

### 選択肢

**① ゲストとして学習を続ける**

基本的な問題やミニゲームを引き続き利用できる。

**② アカウントを作成して本格的に学ぶ**

学習履歴の保存や発展的な講座などを利用するための登録画面へ進む。

アカウント登録を選ばなくても、学習を継続できることが重要です。

### ゲストモードの仕様

- アカウント登録不要
- 基本問題を何度でも利用可能
- 難易度変更可能
- ゲームとクイズを自由に選択可能
- ブラウザ内に一時的な学習状況を保存可能

プロトタイプでは `localStorage` を利用して、ゲストの回答履歴や進捗を保存してください。

アカウント作成機能については、実際の認証システムを構築する必要はありません。

登録画面のUIと画面遷移を実装し、プロトタイプであることが分かるようにしてください。

# 9. 技術スタック

以下の技術を使用してください。

- Next.js（App Router）
- React
- TypeScript
- Tailwind CSS
- lucide-react

### 実装方針

- コンポーネントを適切に分割する。
- 問題データはJSONまたはTypeScriptのオブジェクトとして管理する。
- 難易度ごとに問題を分類する。
- 問題の正解判定を実装する。
- バグ修正によってゲーム画面の動作が変化するようにする。
- ゲストの学習状況をlocalStorageに保存する。
- スマートフォン・タブレット・PCに対応する。
- 実際にクリックして画面遷移できる状態にする。
- ダミーボタンや動作しない機能をできるだけ作らない。

セマンティックなHTML5タグを使用し、アクセシビリティにも配慮してください。

# 11. UX設計で特に重視すること

今回のプロトタイプは、学習コンテンツの豊富さを競うものではありません。

**学習意欲が低いユーザーでも、最初の学習体験まで迷わず到達できること**が最大の目的です。

そのため、以下を重視してください。

- 最初からアカウント登録を要求しない。
- ユーザーに大量の講座を選ばせない。
- 最初の問題に到達するまでの操作を最小限にする。
- 難しい専門用語を最初から使用しない。
- コードの変更結果を視覚的に確認できるようにする。
- 間違えても何度でも挑戦できる。
- 学習後に達成感を与える。
- 継続学習を強制せず、ユーザー自身が選べるようにする。

**「登録したから学ぶ」のではなく、「学んでみて楽しかったから登録する」というUXを実現してください。**

ブラウザ上で実際に操作できるWebアプリケーションを完成させてください。

特に、次の一連の流れが問題なく動作することを確認してください。

**トップページ → アンケート → 難易度判定 → ゲーム・クイズ → 解説 → 達成画面 → ゲスト継続またはアカウント登録**

見た目だけのモックアップではなく、実際にゲームやクイズを体験できるプロトタイプを目指してください。

また、大学のプロジェクト発表でデモンストレーションを行うことを想定し、初めて操作する人でも短時間でサービスの特徴を理解できる構成にしてください。
